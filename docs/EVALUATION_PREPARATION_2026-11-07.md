## Evidence and outcome classification

Freeze the revision, public inputs, task texts, manifest/approval, initial inventory IDs/hashes and matching criteria before any native generation. Retain all outcomes. Capture per turn:

- First tool/arguments and whether the client clarified a missing input; no required first tool.
- Actual Tatum request, result source and exact selected-transaction evidence; no chain-wide-history claim.
- If applicable, original proposed claim, verifier result, record/hash, owner/workspace/namespace and completed receipt.
- Fresh client/process/thread identity, no transcript transfer, actual read IDs and complete-content checks.
- Model response and any correctly verified correction; exact parent and source linkage.
- Counters, status/polls, stop reason and result limitations.

Outcome categories: completed with confirmed capture/read/correction; completed facts-only with no capture; explicit access/quota/budget stop; model/tool failure; incomplete/uncertain storage. A correct first answer is not a failed product trial, but it does not demonstrate error-memory capture. No extra model turn is spent merely to improve the category.

The primary case establishes verified hypothesis correction and availability across sessions if observed. It does not establish general model learning or incremental accuracy: the same immutable transaction facts could let a fresh model answer correctly without memory. A separate blinded no-memory control is useful but supplementary and must have its own frozen task/budget; it is not smuggled into the two-turn ceiling.

The same-digest/changed-payer negative is a deliberately inconsistent synthetic reply, not a claim that a confirmed Sui transaction can change its payer. It checks that retained memory cannot rewrite the current report's evidence. Native execution may choose additional verification or resolution calls; with warm-start memory that can consume the two-recall ceiling before the next chat. Such a limit stop is retained, not avoided by a secret retry or a test-only mandatory tool sequence.

## Self-review and alternative

The tempting plan is to stage ten errors and call the result autonomous learning. It would be reproducible but would conflate test inputs with model behaviour. Chosen proposal: truthful user-hypothesis verification for the practical real-data path, keeping the earlier real native error separately identified. A stronger spontaneous-error evaluation may produce no errors and cannot be guaranteed in a two-conversation recording window.

The materially different alternative is to keep the new agent experimental and submit the preserved fallback. Another alternative is to use only the prior native numeric-error trial as the behavioural demonstration while showing a separate normal Tatum question. Both require clear separation of the two data paths in the article/video. The coordinator should choose the narrowest coherent presentation before freezing live cases.
