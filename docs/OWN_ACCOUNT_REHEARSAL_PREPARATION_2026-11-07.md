## Independent parent ownership and cleanup

Child admission can fail before the child claims a key. Therefore `agent-own-exec.mjs` provides an independent parent. Metadata-only `capture-spec.json` binds the reviewed root, context/plan hashes, exact capture path, parent directory identity and expected public Tatum account. The capture helper creates its0600 file exclusively and durably records dev/inode/birthtime/owner before writing any secret bytes. Clipboard data is handled internally and cleared; it is never an argument, console output or model environment.

`--execute` owns one parent execution, opens child stdout/stderr as0600 descriptors and invokes the exact frozen child. Its finally block cleans only the capture-owned file even if the child rejects source, lineage, missing/expired grant or bootstrap. A replaced file, hardlink, foreign owner/mode or changed parent stops cleanup without broad unlink. Key absence and cleanup outcome are recorded. The child's independent cleanup remains defense in depth. A cleanup failure is a visible stop, not hidden success.

Clipboard clearing runs even when clipboard reading fails. Success explicitly requires a successful pbcopy exit status; a clear failure stops, records clipboardCleared:false and cleans the ownership-bound captured copy. Native client environments remove ACCESS_TOKEN sentinels as well as API keys/delegate/MemWal/Tatum variables. No real clipboard or environment secret values are used in the offline tests.

The actual grant must use the timestamp observed on the real Free page. Capturing the key does not refresh that timestamp or any operation counter. No real grant is generated by preparation. The parent and helper must be frozen before UI/copy begins; raw logs stay private.
